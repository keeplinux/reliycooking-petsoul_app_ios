二、配网双通道

两条通道共用同一套 WiFi 表单、同一套分步状态机与同一套绑定写入逻辑，差异只在下发链路。

主通道 · 扫码 + BLE

出厂二维码携带 sn、型号、MAC 与绑定令牌

1扫码识别解析二维码得到设备身份
2自动连接 BLE手机直连设备 GATT 会话
3WiFi 配网表单录入 SSID 与密码，校验 2.4G 频段
4BLE 下发配置设备连路由器取 IP 并回执
5云端绑定写入设备列表，返回首页

保底通道 · AP 热点

二维码丢失、WiFi 变更、BLE 故障时的兜底

1设备开热点名为 silifield，密码与热点名相同
2手机连热点需选择「保持连接」并关闭自动切换网络
3App 轮询 192.168.4.1读取 sn、MAC 与设备绑定令牌
4自动添加为「待配网」首页横幅提示并直接给出配网入口
5手动配网并绑定复用同一套表单与状态机
失败回退是自动打通的一环：BLE 阶段失败（搜不到设备 / 连接超时 / 设备无响应）时，失败页会直接渲染「改用保底配网」按钮，一键跳转到 HotspotBind 并自动开启检测，用户不需要自己找入口。

三、设备状态机

设备按 sn 作为唯一键去重，已配网设备不会被保底轮询降级。

pending · 待配网 →完成 WiFi 配网并绑定 bound · 已配网 ↺用户移除设备 从列表删除
  • 进入 pending保底热点探测到设备后自动写入，wifiSsid 为空，online 为 false。
  • 转移到 bound配网成功回调写入 wifiSsid 与绑定来源，online 置为 true，boundAt 保留首次绑定时间。
  • 持久化整个设备列表写入 localStorage（键 pet-smart-app:devices），刷新后绑定关系不丢失；退出登录时清空。

五、保底方案评估

对「设备自建 silifield 热点供用户手动配网」这一方案的结论与需要注意的点。

方案成立 这是行业标准做法（AP 配网 / 兼容模式），米家、涂鸦等都有同类兜底通道。它真正解决的是首次绑定无法扫码和蓝牙模块故障两类问题，必须保留。
需要修正 SSID 唯一性：所有设备都叫 silifield 时，多台设备同时处于保底模式会出现同名热点，手机无法区分目标。建议出厂热点名带 SN 后缀（silifield-A7C3）。
需要修正 密码等于 SSID 无安全性：热点名已知且密码公开，附近任何人都能连上并尝试配网。量产版本建议用机身贴纸上的独立密码，或复用二维码里的绑定令牌做一次设备鉴权，令牌不匹配则拒绝配网。
需要修正 手机连上热点后没有外网：Android 可能自动切回蜂窝网络或原 WiFi，导致探测失败。界面必须明确引导用户选择「保持连接」并关闭自动切换网络，否则这个兜底通道在现场会显得「时灵时不灵」。
实现约束 探测方式：手机连上设备热点后，通过固定网关 http://192.168.4.1/api/info 读取设备信息，这是模组 AP 模式的通用做法。当前 Capacitor 的 androidScheme 为 https，WebView 内请求 http 属于混合内容，接入真机时需要在原生层放开。
认知修正 「家里 WiFi 变更」其实不需要走兜底通道：设备已在用户局域网内，正常应由云端下发新配置；设备侧长按重置键重回 AP 模式只是补救手段。这条场景的价值在于「设备已被重置且二维码丢了」，不要把它当作常规换网路径来宣传。
体验缺口 配网结果无法即时确认：设备切到 STA 模式后热点消失，手机回到原网络，App 已无法直接读取结果，只能等设备上线后由云端回调。当前演示用「请切回原 WiFi」收尾，真机阶段需要补一条云端状态回执。
